Reviewed from `bac3dbd88` in an isolated worktree. Scope: VMS core components, managers and persistence; API channels/controllers/views; dashboard subscriptions, actions and data presentation; firmware configuration, release and boot recipes; OVCS1 and Mini control wiring. ## Highest-priority unresolved findings

**P1 — OVCS1 ROS authority is inconsistent across actuators ([TASK-100](<../tasks/task-100 - Align-OVCS1-ROS-authority-across-its-actuators.md>)).** The [composer](../../vehicles/ovcs1/lib/ovcs1/vms/composer.ex#L172) selects ROS throttle, direction and steering. [SteeringColumn](../../vms/core/lib/vms_core/components/ovcs/steering_column.ex#L196) and [IBoosterGen2](../../vms/core/lib/vms_core/components/bosch/i_booster_gen2.ex#L244) enable automatic operation only for `:radio`; the [inverter](../../vms/core/lib/vms_core/components/nissan/leaf_aze0/inverter.ex#L238) follows the selected throttle source. Consequently, selecting ROS can authorize propulsion without applying ROS steering or service-brake requests. Establish a complete supported actuator capability set and inhibit unsupported authority. Enabling additional actuators needs a bench-validated decision, not just another enum value in these conditions. Evidence: code trace through the actual OVCS1 wiring; no hardware activation.

**P1 — A configured but unseen speed source is treated as standstill ([TASK-101](<../tasks/task-101 - Require-fresh-inputs-for-VMS-manager-interlocks.md>)).** [ControlLevel](../../vms/core/lib/vms_core/managers/control_level.ex#L145) and [Gear](../../vms/core/lib/vms_core/managers/gear.ex#L64) initialize speed to zero and retain speed/readiness/brake values without consumer-owned deadlines. A local callback probe, with readiness true and a radio request but no speed sample, selected radio. The [OVCS1 ABS producer](../../vms/core/lib/vms_core/components/volkswagen/polo_9n/abs.ex#L15) also republishes held readings without a watcher. A last-zero producer stall therefore cannot be detected by merely testing for nil. Use unknown at startup and explicit sample ages in the consuming interlocks. A skipped regression records the unmet startup requirement.

**P1 — Mini readiness remains true during a reported failure ([TASK-102](<../tasks/task-102 - Derive-Mini-readiness-from-controller-health.md>)).** [OvcsMini.Vms](../../vehicles/ovcs_mini/lib/ovcs_mini/vms.ex#L25) initializes readiness true and its readiness function does nothing. With the main controller absent after boot, the probe produced `vms_status: "FAILURE"` together with `ready_to_drive: true`. That leaves the manager's readiness gate open despite loss of the controller responsible for steering. Derive readiness from current confirmed health, define re-arm behavior, and compute status/readiness consistently in the same tick. A skipped vehicle regression asserts the required false readiness broadcast.

**P1 — Control and diagnostics share a failure budget ([TASK-104](<../tasks/task-104 - Isolate-VMS-control-supervision-from-diagnostics.md>)).** [VmsCore.Application](../../vms/core/lib/vms_core/application.ex#L20) places Repo, Metrics, NetworkInterfaces and vehicle children under one supervisor with default restart limits. Repeated diagnostic failures can exhaust that budget and terminate control children; emitters live outside this subtree. PR309 removes one trigger, not this architecture. Introduce deliberate supervision boundaries and test repeated diagnostic crashes together with the actuator-expiry requirements in TASK-9–18.

**P1 — Automatic steering does not require valid, fresh feedback ([TASK-109](<../tasks/task-109 - Gate-steering-actuation-on-fresh-valid-feedback.md>)).** [SteeringColumn](../../vms/core/lib/vms_core/components/ovcs/steering_column.ex#L145) records readiness/calibration/trimming flags but does not consult them when enabling automatic mode. It also lacks an LWS sample deadline. The PID can use its initial or last angle after feedback stops. Define a pure enable/interlock decision, an explicit feedback deadline and a validated relay/PWM safe sequence. This complements TASK-14/15; tuning validation in PR310 does not fix feedback safety. Evidence: code inspection.

**P2 — Tachometer rollover corrupts speed and distance ([TASK-103](<../tasks/task-103 - Handle-VESC-tachometer-rollover-and-reset.md>)).** [MotorController.tachometer_rotation/3](../../vms/core/lib/vms_core/components/vesc/motor_controller.ex#L616) subtracts signed 32-bit counts directly. `2147483646 → -2147483646` over 100 ms at two pole pairs produced **-214748364600 rpm**, instead of **200 rpm**. The cumulative revolution path is discontinuous too. Use one counter tracker for both paths, covering forward/reverse rollover and device reset; a speed-only modulo fix leaves distance wrong. A skipped regression preserves the rollover requirement.

**P2 — Steering normalization differs between commands, actuation and odometry ([TASK-110](<../tasks/task-110 - Validate-normalized-steering-requests-at-the-VMS-boundary.md>)).** The [ROS field](../../libraries/ovcs_can/priv/can/components/ovcs/0x2B0_ros_actuator_command.yml#L26) represents approximately ±32.768, while [RosActuatorCommand.Steering](../../vms/core/lib/vms_core/components/ovcs/ros_actuator_command/steering.ex#L48) forwards it under a documented [-1,1] contract. Traxxas clamps servo travel, but VehicleMotion scales the raw request into reported steering angle. Define VMS-side range handling and use the same validated request for both. The deliberate hold-last-steering policy on link loss should remain an explicit decision.

## API and dashboard follow-ups

- **[TASK-105](<../tasks/task-105 - Reject-malformed-metric-channel-subscriptions.md>):** Unknown atom names and malformed subscription payloads raise inside MetricsChannel. Callback probes produced ArgumentError and FunctionClauseError. A valid but absent unsubscribe already succeeds; preserve that behavior. Validate payloads and permitted identifiers without atom creation or raising.
- **[TASK-106](<../tasks/task-106 - Return-not-found-for-unknown-dashboard-pages.md>):** An unknown dashboard page raises BadMapError at the unchecked `.blocks` lookup. Return 404, and define behavior when the optional dashboard configuration is absent.
- **[TASK-107](<../tasks/task-107 - Expose-metric-and-channel-freshness-in-the-dashboard.md>):** Metrics keeps last values indefinitely without sample age. LiveContent correctly warns on socket disconnection, but a stopped producer or channel-only failure can leave old values looking current. Track source validity and channel health separately; retransmission is not a fresh measurement.
- **[TASK-108](<../tasks/task-108 - Correct-the-network-payload-utilization-estimate.md>):** The displayed network “Load” is received payload utilization assuming exactly one second. A counter reset produced -1%; a two-second interval carrying 12,500 bytes at 500 kbit/s displayed 20% instead of 10%. Use elapsed time/reset handling and an accurate label; CAN framing and bit stuffing are not represented by payload-byte counters.
- NumberAction's Enter handler bypasses the pending button state, so tuning requests can overlap. Make pending behavior consistent at the shared posting boundary; server-side action serialization must remain authoritative.
- Firmware builds use `npm install`; use the lockfile deterministically with `npm ci`. The claimed per-file vehicle firmware fallback also needs a fixture for a vehicle overriding only one resource: current resource paths share the directory chosen from `config.txt`.

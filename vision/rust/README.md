# vision/rust

Cargo workspace of the programs `vision_core` runs as Ports.

| Crate | What it does |
|---|---|
| `camera_capture` | Captures frames through libcamera and writes them as JPEG records or, with `--format grey`, as grey records of their luma |
| `hailo_detect` | Runs a compiled model on a Hailo accelerator through HailoRT and writes detections |
| `qnn_detect` | Runs a model's QNN context binary on a Qualcomm Hexagon NPU and writes detections, YOLOX's boxes decoded; its statistics line, every minute, gives the mean time per request of each stage: waiting for it (`idle`), reading it, the letterbox, the execution's stages (`qnn`), decoding and the reply |
| `qnn_segment` | Runs a semantic segmentation model's QNN context binary on a Qualcomm Hexagon NPU over a band of an RGB image, resized to the model's input, and writes each output cell's class; its statistics line, every minute, gives the mean time per request of each stage: waiting for it (`idle`), reading it, the resize, the execution's stages (`qnn`), the argmax and the reply |
| `qnn` | Library the QNN Ports share: a context binary's first graph run on the Hexagon NPU through QNN's HTP backend under a performance profile's power vote (`--performance <profile>`, `burst` by default), each execution timed, and the Ports' statistics line; an execution's stages are the wall time around `graphExecute`, the times QNN's profile reports inside it (`QNN execute`, the remote procedure call as the CPU and as the HTP time it, `host RPC` and `HTP RPC`, and the graph on the HTP, `HTP`), and reading the profile after it (`profile read`) |
| `detection` | Library the detection Ports share: their record protocol, the letterbox between the caller's image and the model's input, and non-maximum suppression; `qnn_segment` shares its bilinear resize |
| `v4l2_capture` | Captures two CSI cameras over raw V4L2, on the OKdo Nano C100 or, through CAMSS in packed 10-bit Bayer, on the Arduino VENTUNO Q, locks the right sensor's frame starts to the left one's by adjusting its vertical blanking, holds both lens actuators at the `focus` setting when the system drives them, and writes grey frame pairs; given one capture node and sensor (`--video`, `--sensor`), it captures that camera alone, such as the IMX477 on the VENTUNO Q in packed 12-bit Bayer, and writes its outputs, one record per output per frame tagged with the output's index (OUTPUT_FRAME), each `--output` made by the software conversion with grey-world white balance (`cpu:<width>x<height>`), demosaiced bilinearly at the capture's size or 2×2 at half of it, or averaged from an earlier output in blocks of a whole fraction of its size (`from:<index>:<width>x<height>`), the conversion behind a processor trait so another processor, such as an ISP, slots in beside it; for the IMX477 it follows libcamera's Raspberry Pi pipeline with Raspberry Pi's tuning (lens shading, colour correction matrix of the colour temperature, a chroma denoise at the resolution of the 2×2 cells, and the contrast curve, auto exposure measuring the green after lens shading and white balance, through the curve, before the colour matrix and the denoise; the `ccm=false` and `denoise=false` settings leave the matrix and the denoise out), other sensors take the plain `gamma`; it converts each frame, then averages the outputs made from others, in bands of rows on `threads` threads, 1 to 8, by default 3 with an output at the capture's size and 1 otherwise, and writes each frame's outputs on a writer thread while the next one converts; its statistics line, every minute, gives the time per frame of the conversion, the averaging and the writes. `v4l2_capture/libcamera_tuning.py` writes a sensor's tuning module from libcamera's tuning file |
| `jpeg_codec` | Encodes grey or RGB images as JPEG, colours depth previews, and decodes JPEG frames to grey, for `VisionCore.Jpeg` |
| `framing` | The `{:packet, 4}` framing the binaries share: a big-endian length prefix, little-endian scalars |

The Elixir side of the protocol is `VisionCore.Camera.LibCamera`, `VisionCore.Detection.Backend.Hailo`, `VisionCore.Detection.Backend.Qnn`, `VisionCore.Camera.V4L2` and `VisionCore.Jpeg`; `qnn_segment`'s records are described in `qnn_segment/src/protocol.rs`. The stereo stages' native Port, `stereo_match`, is nx_stereo's: it builds it when it compiles.

The `device` feature of `camera_capture` and `hailo_detect` links the device libraries: libcamera from the system, `libhailort` from [`libraries/hailort`](../../libraries/hailort), whose header and library directories `../core/Makefile` passes as `HAILORT_INCLUDE_DIR` and `HAILORT_LINK_DIR`. Without it the crates build on any host, all but `qnn`, `qnn_detect` and `qnn_segment`, which is what the unit tests use:

```sh
cargo test
```

For the `rpi5` Nerves target, `../core/Makefile` runs the cross-build, for the Cortex-A76, and installs `camera_capture`, `hailo_detect` and `jpeg_codec` into `vision_core`'s `priv/`; for `okdo_c100` it installs `v4l2_capture`, which needs only libc, and `jpeg_codec`; for `arduino_ventuno_q`, for the Cortex-A78, those two, `qnn_detect` and `qnn_segment`. `qnn` and the Ports on it are outside the workspace's default members: `qnn`'s bindings are generated with bindgen from the QNN headers of the QAIRT archive `mise run fetch-qairt` caches, which the Makefile extracts, and nothing derived from them is committed. Their unit tests need those headers too: `QAIRT_INCLUDE_DIR=<qairt>/include/QNN cargo test -p qnn -p qnn_detect -p qnn_segment`. The `vision_core` tests build `jpeg_codec` for the host themselves. The workspace needs the `aarch64-unknown-linux-gnu` Rust target (`mise install`) and a host libclang for bindgen.
